# Debate — Bull Case vs. Bear Case

An adversarial review of the central question: **is an orbital AI-inference
data center on Neutron a worthwhile venture?** Not just "is it feasible" —
*should Rocket Lab do it.*

Two roles, each producing one document, refined over rounds:

- **Bull** → [bull_case.md](bull_case.md) — the case **for**. Why this is a
  worthwhile venture.
- **Bear** → [bear_case.md](bear_case.md) — the case **against**.

## Rules of the debate

1. **Every claim cites a source.** Point to a project research doc, or do
   independent web research and cite the URL. No unsourced assertions — ever.
   Never lie, never overstate; a strong case is built only on what is real.
2. **They read each other.** Each round, a side reads the other's current
   document and cross-checks it — calling out any claim that is unsourced,
   misread, or contradicted by the evidence.
3. **Rounds.** The **Bull opens** (round 1: bull_case.md). The Bear then reads
   it and writes bear_case.md (its own case + rebuttal of the Bull). Then they
   alternate: each subsequent round, a side reads the other's latest and
   appends a new "Round N" section — sharpening, conceding what is fair,
   rebutting what is not.
4. **The goal is robustness, not winning.** The value is two concrete,
   fully-traceable documents that survive cross-examination — so the project's
   final conclusion can stand on tested ground.

## How this feeds the project

The bull and bear documents are inputs to the `feasibility-forge` conclusion
document. The conclusion does not pick a "winner" — it states the verdict that
survives both cases, with the honest caveats the Bear surfaced.
